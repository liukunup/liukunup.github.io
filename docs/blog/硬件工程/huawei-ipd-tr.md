## 前言

本文面向测试小白，系统介绍华为 IPD 流程各阶段（概念→计划→开发→验证→发布→生命周期）的软硬件测试活动及准出条件。通过表格形式清晰展示，便于理解和记忆。

## IPD 流程与测试全景图

```
概念阶段 → 计划阶段 → 开发阶段 → 验证阶段 → 发布阶段 → 生命周期
   ↓           ↓           ↓           ↓           ↓
 TR1        TR2/TR3      TR4/TR5      TR6        GA
```

## 各阶段测试活动与准出条件一览表

| 阶段 | 评审点 | 软件测试活动 | 硬件测试活动 | 准出条件 |
|------|--------|--------------|--------------|----------|
| **概念阶段** | CDCP | 需求评审、可测试性分析 | 需求评审、硬件方案初评 | 需求可验证、无歧义 |
| **计划阶段** | TR2/TR3 + **PDCP** | 测试策略制定、测试计划编写 | 硬件方案评审、DFM 评审 | PDCP 通过 |
| **开发阶段** | TR4/TR4A | 单元测试、集成测试、SDV | 详细设计、单板测试、SDV | SDV 通过、代码合入 |
| **验证阶段** | TR5 + SIT | 系统测试、性能测试、Beta 测试 | SIT、SVT、可靠性测试 | SVT 通过、Beta 通过、TR6 通过 |
| **发布阶段** | **ADCP** | 验收测试、发布准备 | 小批量试产、认证测试 | ADCP 通过、GA 就绪 |
| **生命周期** | LDCP | 线上监控、问题修复 | 现场问题处理 | 按需迭代 |

> **注**：PDCP（Plan Decision Checkpoint）是计划阶段的决策评审点，是 IPD 中最重要的评审点之一，决定是否正式投入资源进入开发阶段。
| **开发阶段** | TR4/TR4A | 单元测试、集成测试、SDV | 详细设计、单板测试、SDV | SDV 通过、代码合入 |
| **验证阶段** | TR5/SIT | 系统测试、性能测试、Beta 测试 | SIT、SVT、可靠性测试 | SVT 通过、Beta 通过、TR6 通过 |
| **发布阶段** | ADCP | 验收测试、发布准备 | 小批量试产、认证测试 | ADCP 通过、GA 就绪 |
| **生命周期** | - | 线上监控、问题修复 | 现场问题处理 | 按需迭代 |

## 一、概念阶段（TR1）

### 阶段目标
明确需求，评估技术可行性，确定是否启动项目。

### 软件测试活动

| 活动 | 内容 | 输出物 |
|------|------|--------|
| 需求评审 | 评审需求的完整性、可测试性、一致性 | 需求评审记录 |
| 可测试性分析 | 识别难以测试的需求，提前预警 | 可测试性分析报告 |
| 测试策略初稿 | 初步定义测试范围和方法 | 测试策略初稿 |

### 硬件测试活动

| 活动 | 内容 | 输出物 |
|------|------|--------|
| 硬件需求评审 | 评审硬件需求的完整性和可行性 | 硬件需求评审记录 |
| 硬件方案初评 | 初步评估技术方案、器件选型 | 硬件方案评估报告 |

### 准出条件
- ✅ 需求文档评审通过
- ✅ 需求无歧义、可验证
- ✅ 可测试性风险已识别

## 二、计划阶段（TR2/TR3）

### 阶段目标
完成系统设计，制定详细计划，包括测试计划。

### 软件测试活动

| 活动 | 内容 | 输出物 |
|------|------|--------|
| 测试策略制定 | 定义测试范围、方法、工具、资源 | 测试策略文档 |
| 测试计划编写 | 制定详细的测试计划，包括里程碑 | 测试计划 |
| 测试用例设计（初稿） | 设计测试用例初稿 | 测试用例库 |
| 测试环境规划 | 规划测试环境、测试数据 | 环境配置方案 |

### 硬件测试活动

| 活动 | 内容 | 输出物 |
|------|------|--------|
| 硬件方案评审（TR2） | 评审系统架构、接口定义 | 架构评审报告 |
| 详细设计评审（TR3） | 评审详细设计、器件选型 | 设计评审报告 |
| DFx 评审 | 评审可制造性、可测试性、可维护性 | DFx 评审报告 |
| 单板方案评审 | 评审单板设计、原理图 | 单板评审报告 |

### 准出条件
- ✅ 测试策略通过评审
- ✅ 测试计划通过评审
- ✅ 硬件方案通过 TR2/TR3 评审
- ✅ DFx 风险已识别并有对策

### PDCP：计划决策评审点

PDCP（Plan Decision Checkpoint）是 IPD 流程中最重要的评审点之一，位于计划阶段末、正式进入开发阶段前。PDCP 评审通过后，项目将正式锁定资源投入，因此也被称为**"定方案"评审**。

#### PDCP 四大评审维度

| 评审维度 | 核心问题 | 评审要点 |
|----------|----------|----------|
| **开发计划可行性** | 有没有一个可执行的开发计划？ | 产品定义、开发计划、测试计划、资源分配、经验教训 |
| **业务潜力评估** | 这个概念是否仍有充分的业务潜力？ | 财务分析、ROI、盈利时间、相对优先级 |
| **产品包竞争力** | 产品包是否有竞争性和吸引力？ | 客户满意度、竞争优势、是否符合公司策略 |
| **风险管理** | 对于已确定的风险，有哪些规避计划？ | 关键风险、规避计划、变更影响 |

#### PDCP 评审详细检查清单

**1. 开发计划可行性**

| 检查项 | 内容 | 通过标准 |
|--------|------|----------|
| 产品定义 | 产品/产品包定义是否清晰完整 | 定义文档评审通过 |
| 开发计划 | 开发计划是否可执行 | 计划评审通过 |
| 测试计划 | 测试计划是否完整 | 测试策略和计划评审通过 |
| 制造计划 | 制造、服务投资计划是否明确 | 制造计划评审通过 |
| CBB 复用 | 是否优化了共用部件使用 | CBB 复用策略明确 |
| 经验教训 | 是否吸取了以前项目的经验教训 | 经验教训已应用 |
| 资源分配 | PDT 成员是否确定，资源是否到位 | 资源承诺到位 |
| 计划评审 | 计划是否考虑了所有关键角色的意见 | 跨部门评审通过 |

**2. 业务潜力评估**

| 检查项 | 内容 | 通过标准 |
|--------|------|----------|
| 财务分析 | 财务分析是否足够详细 | 销售量、ROI、盈利时间清晰 |
| 收益评估 | 预期收益相对于风险和资源是否适当 | 收益风险比合理 |
| 优先级 | 相对于其他产品包的优先级 | 优先级明确 |

**3. 产品包竞争力**

| 检查项 | 内容 | 通过标准 |
|--------|------|----------|
| 客户满意度 | 如何确保客户满意度超过竞争对手 | 策略明确 |
| 市场验证 | 如何证实产品对客户有吸引力 | 市场验证计划 |
| 竞争优势 | 发布时能否提供竞争优势 | 竞争优势明确 |
| 策略符合 | 是否符合公司策略 | 符合公司战略 |

**4. 风险管理**

| 检查项 | 内容 | 通过标准 |
|--------|------|----------|
| 风险识别 | 是否识别了所有关键风险 | 风险清单完整 |
| 规避计划 | 是否有规避计划 | 规避计划明确 |
| 变更管理 | 自 CDCP 以来的风险变更 | 变更已评估 |

#### PDCP 前测试准入条件

| 检查项 | 内容 | 要求 |
|--------|------|------|
| 测试策略 | 测试策略是否评审通过 | 评审通过 |
| 测试计划 | 测试计划是否详细完整 | 评审通过 |
| 测试用例 | 测试用例是否设计完成 | 初稿完成 |
| 测试环境 | 测试环境是否规划完成 | 方案确定 |
| 测试资源 | 测试人员是否到位 | 资源承诺 |
| DFx 评审 | 可测试性评审是否通过 | 通过 |

#### PDCP 决策结果

| 决策 | 含义 | 后续行动 |
|------|------|----------|
| **Go** | 通过，可进入开发阶段 | 正式锁定资源投入 |
| **Go with Risk** | 有条件通过 | 需在开发阶段完成整改项 |
| **Recycle** | 不通过 | 返回计划阶段继续完善 |
| **Kill** | 终止项目 | 项目取消 |

#### PDCP 与 TR2/TR3 的关系

```
计划阶段
├── TR2（系统架构评审）→ 关注架构合理性
├── TR3（详细设计评审）→ 关注设计完整性
└── PDCP（计划决策评审）→ 关注商业可行性和资源承诺
         ↓
      TR2/TR3 通过是 PDCP 的必要条件
      PDCP 通过才能进入开发阶段
```

#### PDCP 准出条件汇总

| 类别 | 准出条件 |
|------|----------|
| **技术类** | TR2/TR3 评审通过、测试策略和计划评审通过、DFx 风险可控 |
| **业务类** | 财务分析通过、产品包竞争力评估通过、业务潜力确认 |
| **计划类** | 开发计划可执行、资源分配到位、PDT 成员确定 |
| **风险类** | 风险清单完整、规避计划明确 |

## 三、开发阶段（TR4/TR4A）

### 阶段目标
完成编码和单元测试，进行系统集成和验证。

### 软件测试活动

| 活动 | 说明 | 准出标准 |
|------|------|----------|
| **单元测试** | 对每个模块进行独立测试 | 分支覆盖率 ≥80% |
| **代码检视** | 同行评审代码质量 | 严重问题清零 |
| **静态代码分析** | 使用工具检查代码问题 | 高危问题清零 |
| **集成测试** | 模块间接口和集成测试 | 核心接口通过率 100% |
| **SDV** | 系统设计验证，原型机测试 | 功能覆盖率 ≥95% |

### 硬件测试活动

| 活动 | 说明 | 准出标准 |
|------|------|----------|
| **单板测试** | 原理图验证、信号完整性测试 | 测试通过率 100% |
| **单板功能测试** | 电源、时钟、通信等基础功能 | 功能测试通过 |
| **SDV** | 系统设计验证，样机测试 | 规格符合度 ≥95% |
| **环境测试（初测）** | 高低温、振动等环境摸底 | 基础环境测试通过 |

### TR4 评审要点
- 代码符合设计规范
- 单元测试覆盖率达标
- 模块间接口正确
- 文档已更新

### 准出条件
- ✅ TR4 评审通过（代码质量、单元测试）
- ✅ TR4A 评审通过（SDV 原型机验证）
- ✅ 遗留缺陷已评估，风险可控

## 四、验证阶段（TR5/TR6）

### 阶段目标
全面验证产品是否满足市场需求，准备上市。

### 软件测试活动

| 活动 | 说明 | 准出标准 |
|------|------|----------|
| **SIT** | 系统集成测试，功能性能验证 | 测试用例执行率 100% |
| **系统测试** | 完整系统功能测试 | 严重缺陷清零 |
| **性能测试** | 验证性能指标达标 | 性能指标 100% 达标 |
| **可靠性测试** | 长时间运行、压力测试 | 无可靠性问题 |
| **Beta 测试** | 客户试用，收集反馈 | 客户满意度 ≥4 分 |
| **安全测试** | 漏洞扫描、渗透测试 | 高危漏洞清零 |

### 硬件测试活动

| 活动 | 说明 | 准出标准 |
|------|------|----------|
| **SIT** | 系统集成测试，硬件软件联调 | 系统稳定运行 |
| **SVT** | 系统验证测试，产线随机抽样 | 随机抽样合格率 ≥95% |
| **可靠性测试** | HALT/ALT/EMC/安规等 | 全部通过 |
| **认证测试** | 入网/CE/FCC 等认证 | 获得认证证书 |
| **试产验证** | 小批量试产，验证工艺 | 试产良率 ≥95% |
| **可服务性验证** | 安装、维护、故障诊断验证 | 全流程验证通过 |

### 测试分层对照

| 测试类型 | 测试对象 | 测试环境 | 目的 |
|----------|----------|----------|------|
| SDV | 原型机 | 实验室 | 验证设计是否实现规格 |
| SIT | 初试产品 | 实验室 | 验证系统集成是否正确 |
| SVT | 量产产品 | 产线随机抽样 | 验证批量一致性 |

### 验证阶段时间轴

```
第1-4周    第2-6周    第3-8周    第4-8周    第6-10周   第8-12周
  ↓          ↓          ↓          ↓          ↓          ↓
┌─────────┬─────────┬─────────┬─────────┬─────────┬─────────┐
│ SVT启动 │Beta测试 │认证测试 │试产爬坡 │资料发布 │TR6+ADCP│
└─────────┴─────────┴─────────┴─────────┴─────────┴─────────┘
```

| **计划阶段** | **PDCP** | TR2/TR3 通过 + 测试计划通过 + 业务可行性确认 |
| **开发阶段** | TR4/TR4A | SDV 通过、TR4 通过 |
| **验证阶段** | TR5/TR6 | SVT 通过、Beta 通过、TR6 通过 |
| **发布阶段** | **ADCP** | ADCP 通过 |
| **生命周期** | LDCP | 补丁测试通过 |

### IPD 四大决策评审点（DCP）对照

| 评审点 | 阶段 | 核心问题 | 决策 |
|--------|------|----------|------|
| **CDCP** | 概念阶段末 | 做不做？ | 概念是否成立 |
| **PDCP** | 计划阶段末 | 怎么做？ | 方案是否可行 |
| **ADCP** | 验证阶段末 | 能否上市？ | 产品是否就绪 |
| **LDCP** | 生命周期末 | 是否退市？ | 生命周期结束 |

## 九、常见问题

### Q1: SDV、SIT、SVT 有什么区别？

| 测试 | 对象 | 环境 | 目的 |
|------|------|------|------|
| SDV | 原型机 | 实验室 | 验证设计规格是否实现 |
| SIT | 初试产品 | 实验室 | 验证系统集成是否正确 |
| SVT | 产线随机抽样 | 产线 | 验证批量生产一致性 |

**记忆口诀：**
- SDV = **原**型机 **D**esign（设计验证）
- SIT = **初**试产品 **I**ntegration（集成验证）
- SVT = **抽**样 **V**erification（验证抽样）

### Q2: TR5 和 TR6 有什么区别？

| 评审 | 时机 | 关注点 |
|------|------|--------|
| TR5 | 开发阶段末期 | 设计是否满足规格 |
| TR6 | 验证阶段末期 | 是否具备量产条件 |

### Q3: Beta 测试和 SVT 有什么区别？

| 测试 | 谁测 | 在哪测 | 关注什么 |
|------|------|--------|----------|
| Beta | 客户 | 客户现场 | 用户体验、真实场景 |
| SVT | 测试团队 | 产线抽样 | 批量一致性 |

## 十、总结

### IPD 测试全景

```
┌────────────────────────────────────────────────────────────────┐
│                        IPD 测试全景                             │
├────────────────────────────────────────────────────────────────┤
│  概念 ──→ 计划 ──→ 开发 ──→ 验证 ──→ 发布 ──→ 生命周期     │
│    │        │        │        │        │        │            │
│   TR1      TR2      TR4     TR5     ADCP      GA            │
│           TR3     TR4A     TR6                           │
│                            │                               │
│                      ┌─────┴─────┐                         │
│                      │  验证支柱  │                         │
│                      │  SIT      │                         │
│                      │  SVT      │                         │
│                      │  Beta     │                         │
│                      │  认证     │                         │
│                      └───────────┘                         │
└────────────────────────────────────────────────────────────────┘
```

### 核心要点

1. **概念阶段**：明确需求，评估可测试性
2. **计划阶段**：制定测试策略和计划
3. **开发阶段**：完成 SDV，原型机验证
4. **验证阶段**：SIT + SVT + Beta + 认证，全面验证
5. **发布阶段**：ADCP 决策，量产就绪
6. **生命周期**：线上运维，持续改进
